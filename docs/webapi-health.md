# WebAPI 健康检查

管理端和客户端在所有环境提供 `/healthz`，无需登录。全部检查通过时返回 HTTP 200 与纯文本 `Healthy`；任一检查失败时返回 HTTP 503 与 `Unhealthy`。响应禁止缓存，不向调用方提供组件连接信息。HEAD 不返回正文。

| 检查项 | 目标 |
|---|---|
| Business.Write | 业务写连接 |
| Business.Read | 业务读连接，未配置时回退写连接 |
| Log.Write | 日志写连接目标，包括使用本地文件日志时 |
| Business.Cache | 向业务缓存写入十秒有效的 `cacheHealthCheck` 空字符串 |
| EventBus | 实际事件后端：数据库连接或 Redis PING |
| Log.Read | 仅管理端，使用日志查询连接 |

数据库探测执行 `SELECT 1`，三十秒未完成则发送取消，不依赖业务表，也不创建或迁移表。连接身份登记与取消统一使用 `repository_core::postgres_operation::PostgresOperation`：独占事务连接，通过 PID、后端启动时间和事务内随机标记定位当前操作；取消后不复用连接，使用同认证/TLS 的独立控制连接终止后端并确认结束。只读连接仅开放健康检查契约，不向调用方公开底层写连接。缓存探测不读取、删除该键，不额外探测分布式锁。

宿主启动十秒后开始后台检查，之后每六十秒执行一次；一轮达到三十秒或宿主停止时，取消信号传给各组件并等待清理，失败写入诊断日志。数据库取消控制过程最多十秒，其中服务器终止确认最多五秒；清理与其他资源共用宿主停机期限，期限耗尽后仍可能被强制结束。连接或取消权限故障不能保证服务器端操作立即结束。

`HealthState::health_report_with_cancellation` 提供可取消入口，`AppState` 将同一令牌传给业务库、日志库、事件后端与缓存等待；旧 `health_report` 调用保持可用。后台检查不再用丢弃整轮 future 代替数据库取消。`/healthz` 提取每个请求独立的 `RequestCancellation` 并传入该入口。共享宿主跟踪请求处理任务；连接断开先取消令牌，处理任务继续到协作清理完成，不直接丢弃仍在清理的数据库 future。HTTP 服务排空后，宿主使用同一个停机截止时间等待这些任务，期限耗尽或宿主异常释放时取消剩余任务。

健康状态不证明表结构、写权限、复制延迟和业务操作正确。`task_service` 不提供 HTTP 健康接口。
