# WebAPI 健康检查

管理端和客户端通过 `/healthz` 检查依赖是否可用，适合供部署探针和监控系统调用，无需登录。

```powershell
curl.exe -i http://127.0.0.1:3000/healthz
```

全部通过时返回 HTTP 200 和纯文本 `Healthy`；任一失败时返回 503 和 `Unhealthy`。响应禁止缓存，HEAD 不返回正文。

## 检查范围

| 检查项 | 目标 |
| --- | --- |
| Business.Write / Business.Read | 业务写库、只读库 |
| Log.Write | 日志写库目标，使用本地文件日志时也检查 |
| Business.Cache | 写入十秒有效的 `cacheHealthCheck` 空字符串 |
| EventBus | 配置的数据库或 Redis 事件后端 |
| Log.Read | 仅管理端，日志查询连接 |

数据库使用 `SELECT 1`，缓存检查不读取或删除探测键，事件检查不发布消息。新增模块的连接可通过宿主健康检查注册接入。

宿主启动十秒后开始后台检查，此后每六十秒检查一次。单轮三十秒超时后发出取消并等待清理；清理使用宿主剩余停机时间。

## 如何理解结果

健康结果表示依赖探测成功，不保证数据库表结构、写入权限、复制延迟或具体业务操作正确。数据库未迁移时也可能返回健康。

异常时检查宿主日志和对应连接配置。数据库取消需要能够建立控制连接并使用服务器终止功能；连接或权限故障时，服务器端查询可能无法立即结束。

`task_service` 不提供 HTTP 健康接口。
