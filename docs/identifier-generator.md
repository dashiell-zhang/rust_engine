# ID 生成器

每个宿主创建一个 `IdentifierGenerator`，业务实体、日志、队列和数据库事件复用它的克隆。克隆共享节点、序列和租约，不按数据库或组件分别发号。

ID 布局保持为 42 位时间、5 位数据中心、5 位机器和 11 位序列，纪元为 `2022-01-01 00:00:00 UTC`。持久化时间转换由 `identifier_generator::layout` 统一提供。

## 自动分配

三个宿主使用相同的共享 Redis 配置：

```toml
[identifier_generator]
redis_connection = "redis://127.0.0.1:6379/0"
instance_name = "NetEngine.Identifier"
lease_duration_milliseconds = 172800000
```

`redis_connection` 为空时，宿主明确选用 `[cache].connection` 的地址，但不使用业务缓存组件、业务缓存前缀或业务锁。即使业务缓存选择内存模式，自动 ID 节点仍需要 Redis。

参与同一 ID 唯一性范围的所有进程，必须使用相同 Redis 目标、库编号和 `instance_name`。节点键为 `NetEngine.Identifier:Node:0` 至 `NetEngine.Identifier:Node:1023`，与 NetEngine 的默认协调协议一致。更换前缀代表另一个分配范围，不能用宿主名称隔离需要共同保证唯一性的节点。

租约默认两天，可配置范围为 3000 至 2592000000 毫秒，即 3 秒至 30 天；共享范围内的实例应保持一致。节点从随机位置开始扫描，通过带所有者令牌和有效期的 `SET NX PX` 原子占用，再确认所有者及剩余有效期。连接失败、结果未确认或节点耗尽会使初始化失败，不会回退到内存分配或猜测空闲节点。

## 续期与停止发号

节点确认后立即启动独立续期，不等待数据库、事件总线或宿主后台任务初始化完成。续期间隔是租约的三分之一，最多 30 秒；Redis 请求使用 5 秒等待上限。

续期脚本仅延长仍有效且属于当前所有者的键，不创建已过期的键，不覆盖新持有者。发号依据单调时钟计算的本地保守有效期，扣除请求耗时和安全余量。短暂续期故障不立即否定仍有效的租约，但不会延长有效期；超过本地有效期后拒绝生成 ID。若 Redis 键仍有效且同一所有者续期得到确认，可以恢复发号。确认所有权丢失后，本实例永久停止发号，需要修复依赖并重启重新分配。

发号前、等待下一毫秒期间及提交序列前都检查有效性。时钟回拨会返回错误；超过 ID 可表示范围也会返回错误。取消序列溢出等待不会提交新序列状态。

最后一个生成器克隆释放时停止续期。也可以调用 `shutdown().await` 显式停止所有克隆；应先完成仍需要 ID 的日志排空和后台工作。退出不删除 Redis 占用，节点保留至自然到期，容量包含近期退出实例的未过期占用。

ID 诊断写入标准错误，不经过数据库日志。Redis 节点键不能当作普通缓存清理或淘汰；若协调数据丢失，应先停止该唯一性范围内的所有发号实例，再恢复分配。

## 固定编号

部署方能够管理唯一节点组合时，同时指定以下两个值：

```toml
[identifier_generator]
data_center_id = 0
machine_id = 1
```

两者必须同时出现且分别介于 0 和 31。固定模式不连接 Redis，不使用租约；不要给多个实例复制相同组合，也不要把固定编号混入自动分配范围。运行过程中不能动态改写节点身份。
