## 双实例实际发号

通过客户端正式 `GET /Authorize/UpdateRoute` 触发权限路由新建。SQL 仅软删除隔离库的一条现有路由，使下一次同步必须生成主键，随后读取记录；没有直接调用生成器或新增 HTTP 入口。

A 启动后至少运行 20 秒，超过 6 秒租期，首次同步返回 200 并创建 9 条有效路由。按当前正式位布局 `(Id >> 11) & 1023` 读取节点位，均为 254。软删除 `User/GetUser` 后调用 B，返回 200，新记录节点为 629；旧记录继续保留软删除状态。

此时 Redis 中节点 254 和 629 的剩余有效期分别为 5776、5930 毫秒。宿主持续运行时占用仍有效，且实际业务记录携带不同节点位。这证明所列双实例运行与续期，不等同于高并发压力或所有取消交错的唯一性证明。

## 所有者替换与节点耗尽

将隔离节点 254 的值替换为另一个所有者、设置 120 秒有效期。A 输出固定的“节点所有权丢失，停止发号，需要重启实例”诊断。再次准备缺失路由后，A 同步返回生产错误 400；数据库总记录仍为 10、有效记录仍为 8，没有补写新 ID。

读取 Redis 确认值仍属于新所有者，剩余有效期约 115 秒，没有被 A 续期脚本覆盖。调用 B 同步返回 200，新记录节点仍为 629。随后仅在隔离 Redis 中恢复 A 的原所有者令牌，再次准备缺失路由；A 仍返回 400，B 仍返回 200，符合确认所有权丢失后需重启的规则。

另用 `B5.Full` 前缀占满 0～1023 共 1024 个节点，运行一个使用该范围的正式客户端。进程明确报告“ID 服务初始化失败：1024 个雪花节点均已占用”，非零退出；没有回退为固定编号或启动正常服务。该情形检查的是启动失败行为，不要求错误退出文案与 .NET 完全相同。

## Redis 暂停、恢复与退出

暂停隔离 Redis 服务，明确等待 8 秒，再准备缺失路由并请求 B。B 返回 400，诊断为节点租约未确认或已失效；数据库总记录 12、有效记录 8，在失败请求前后不变。续期故障日志没有延长本地有效期。

恢复 Redis 后，节点 629 的 PTTL 为 -2（键不存在）。B 随后记录所有权丢失，再次调用仍返回 400。本批使用的是服务暂停导致请求无响应，并未声称覆盖实际网络分区的所有 TCP 交错，也没有验证短故障期间同一所有者成功续期后的恢复分支。

向 A/B 发送正常 SIGTERM，两进程均以 0 退出。启动同配置的新客户端 C，取得节点 188；路由同步返回 200，总记录变为 13、有效记录恢复 9。新生成记录的节点位为 188。

停止 C 前节点 PTTL 为 4465 毫秒；正常 SIGTERM 后进程以 0 退出，键仍存在，PTTL 为 4889 毫秒，表示采样之间发生过最后一次正常续期。稍后读取 PTTL 为 -2，确认退出后没有继续续期，也没有立即释放键。清理前再次确认 A/B/C 进程均不存在。
