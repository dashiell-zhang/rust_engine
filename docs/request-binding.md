# WebAPI 请求绑定

管理端和客户端使用 `webapi_core::extract` 的 `Json`、`Query` 与 `PageQuery`。字段名称按请求 DTO 的声明使用 OrdinalIgnoreCase 匹配，例如 `userName`、`UserName` 和 `USERNAME` 指向同一字段。嵌套的强类型对象同样按各自声明绑定；字典键和 `serde_json::Value` 中的业务属性名保持原样。

JSON 中同一个 DTO 字段重复出现时，已经通过逐项类型校验的赋值以最后一个值为准，包括仅大小写不同的字段名；较早的类型错误不能通过后续赋值覆盖。查询字符串中的标量参数重复出现时使用第一个值。不要依赖重复参数传递互相冲突的业务信息。

`Query`、`PageQuery` 和 `RsaQuery` 的模型使用 `#[derive(common::json_helper::input::QueryModel)]`。宏逐字段复用现有 Serde 声明，收集各字段的第一条错误，所有字段通过后才构造请求对象。无需在处理器中重复检查字段，也不要通过捕获首个错误后删除参数并重试绑定来收集错误。当前宏支持非泛型具名字段模型，模型级 Serde 配置支持 `rename_all`，不支持 `flatten`。

`Json`、`JsonWithBody` 和 `RsaJson` 的请求模型使用 `#[derive(common::json_helper::input::JsonModel)]`，并通过 `#[json(type_name = "源协议类型全名")]` 声明诊断中的模型类型名称。非可空字符串与集合声明必填，字段的 `#[serde(default)]` 保留省略时的初始化行为；显式 null 仍受非可空约束。`#[json(required = "提示")]` 指定必填消息，`#[json(min_length = 1, min_length_message = "提示")]` 声明集合最小长度。源属性名称可用 `#[json(name = "源属性名")]` 覆盖；默认名称为 JSON 字段名首字母大写。Rust Vec 默认对应源 List，源数组额外声明 `#[json(array)]`，用于区分协议类型名。

共享 `read_json_model` 在一次 JSON 值读取中按声明检查根对象、字符串、集合和嵌套对象，不额外反序列化业务模型。类型错误保留原请求字段名、数组索引及 UTF-8 字节位置；比如较早的 `userName: 1` 会立即拒绝，不能被后续合法的同名字段掩盖。只有此前出现的值都通过已声明类型检查后，合法重复属性才保留末值。模型验证仍在转换后运行；动态 JSON 和内部对象/克隆序列化不自动套用这套 HTTP 模型声明。

形态错误、一般语法错误、转换器错误和模型验证错误在公共输入层分别保留类别，由 HTTP 层输出响应。类型诊断覆盖根引用类型、字符串、非可空布尔、字符串数组、对象集合及嵌套对象。非可空 bool 只接受 JSON true/false，显式 null、数字、字符串、对象和数组均作为类型错误；省略字段继续使用其 Serde 默认值。可空值的空白转换仍由显式转换器决定，不套用非可空 bool 的限制。一般截断 JSON、非法字面量、可空数值、日期及其他转换器诊断仍需完善，不能据此认为所有 System.Text.Json 行为已经等价。

非可空 `i8`/`u8` 至 `i64`/`u64`、`f32`/`f64` 字段，以及集合或字典中这些类型的元素，在读取 token 时复用标量转换规则检查格式、范围及 null。字段有 `deserialize_with` 时沿用该转换函数；普通元素使用公共输入适配器。失败交给已有类型诊断响应，携带对应的 `System.Int32`、`System.Int64` 等名称、原始路径、行和 UTF-8 字节位置，并由 HTTP 层补正文参数必填信息。标量校验不构造或重新绑定整个业务模型；业务模型仍在读取成功后绑定一次。自定义数值转换器应保持纯转换，不加入业务操作。

HTTP 普通数值字符串不自动裁剪首尾空白；`i64` 沿用源 LongConverter 的裁剪规则。浮点字符串只将精确拼写的 `NaN`、`Infinity`、`-Infinity` 识别为命名常量，其他字符串解析出非有限值仍拒绝。此规则不扩展到 Query、内部对象/克隆或动态 JSON 的字符串。尚未完成全部浮点边界及两端数值错误响应的实际运行对照。

显式使用 `deserialize_optional_json_scalar` 的可空数值/布尔字段，以及使用 `deserialize_option_i64_from_string_or_number` 的可空 ID 字段，也参与首次值转换校验。空值、空字符串与纯空白保留为 `None`；非空值按目标类型进入公共 JSON 转换器，不先猜成 i64/u64/f64 再转换。这样，可空普通整数不会额外接受首尾空白，可空浮点的命名常量也沿用同一规则。普通可空字符串仍保留字符串语义，不因这个声明变成数值。

源可空转换器通过 `JsonSerializer.Deserialize<T>(ref reader, options)` 独立读取当前值，因此上述转换失败使用内层类型名、路径 `$`，行和字节位置相对于当前原始值计算。错误字符串的位置包括引号、转义原文和 UTF-8 字节，而不是解码后的字符数。对象或数组会先完成当前值的语法/深度读取，再报告无法转为标量；一般语法错误的完整文案仍待对齐。未显式声明这些转换器的 Option 字段、集合元素、Query 和动态文档不自动套用这项语义。日期转换和完整数值边界仍未完成实际运行对照。

以 String 保存协议标量时，通过 `#[json(value, scalar_type = "System.DateTimeOffset")]` 或 `System.Int64` 声明实际类型，并提供字段的 `deserialize_with`。这项声明仅支持非可空标量，宏拒绝缺少转换器、集合、字典或嵌套对象的组合；不会根据字段内容猜测类型。文章/文件 ID、文章创建时间和微信支付通知创建时间已使用声明，非法格式、范围、null 及错误 token 在逐项读取阶段报告协议类型，不能被后续同名属性掩盖。

上述 HTTP 日期字段通过 `common::json_helper::date_time::parse_offset_iso` 读取日期、带分钟或秒的时间、`Z`、`±hh` 和 `±hh:mm` 偏移，支持至多十六位小数秒并只保留前七位。不接受小写分隔标记、首尾空白、闰秒或超过十四小时的偏移；转换到 UTC 后也必须处于 1 至 9999 年范围。未提供偏移时继续使用容器本地时区。Query 与内部日期保留自己的转换入口；本地夏令时缺口/歧义及历史偏移规则尚未完成源端对齐，当前读取器也未完成两端实际日期请求对照。

Linux/Unix 的无偏移日期现在统一通过公共本地时间转换：唯一映射采用对应偏移，重复时刻或不存在的时刻按输入日期查询标准时偏移，并保留原始年月日、时分秒及小数秒。系统时间函数只用于确定偏移，不把其归一化后的时间写回参数。HTTP ISO、Query、内部 JSON 与数据表的本地日期转换共用该能力；各入口自身的格式和范围检查保持独立。历史秒级偏移的 .NET 分钟归一化、非 Unix 平台逐年规则及两端实际运行对照仍未完成。

目标根值读取成功后，公共读取器单独检查是否还有多余内容。后续只允许 JSON 的空格、制表符、回车和换行；第二个值、注释标记或其他字节都产生尾部内容错误，路径为 `$`，位置指向第一个非空白字节。正文参数必填提示由 HTTP 层按路由参数声明补充。可打印 ASCII 按字符显示，其他字节按 `0xXX` 显示，行列按原始 UTF-8 字节计算；合法根 `null` 后有多余内容时也先报告这项错误。已经发现的字段类型错误保持优先。

其余 JSON 语法错误保留公共读取器提供的路径，并走同一正文参数错误装配，不再统一丢弃为根路径。但当前仍使用部分 Serde 语法错误文字；截断输入、非法字面量、标点等源端文案及完整首次失败顺序尚未全部对齐，也未完成两端本轮实际请求对照。

common 显式启用任意精度数字，使行为不依赖其他 crate 的特性合并。读取器识别 serde_json 内部数字协议并保留原始数字表示，浮点外观、指数及超出 i64/u64 的数值不能被误认作对象或提前转换为 f64。真实对象属性通过独立的 newtype 读取边界识别，属性名称碰巧等于内部标记也保持为属性。后续直接反序列化成 serde_json::Value 的动态业务字段仍存在保留名称冲突，已在对齐报告记录，不能将底层读取修正视为整个动态 JSON 链路已完成。

嵌套对象和对象集合通过 `#[json(nested)]` 声明，并在子模型派生 `JsonModel`，错误路径保留属性名称与数组索引。只在转换成功后返回模型验证错误，格式错误仍由 JSON 绑定处理；不会把一个格式无效的字段替换成有效业务输入。缺失或空引用在验证过程中使用临时占位以便继续检查其他字段，存在验证错误时不会把模型交给处理器。作为字符串保存的数值 ID、日期等协议值应使用 `#[json(value)]`，由其原转换器处理类型和范围，不能误当作普通必填字符串。

`JsonModel` 当前支持非泛型具名字段、显式嵌套与现有命名方式，不支持 `flatten` 或跳过反序列化字段。模型级验证不改变内部 JsonHelper、响应模型或动态字典键；第三方协议只有显式使用该请求模型声明时才参与验证。格式转换错误的完整 JSON 路径/位置提示及 Query 与正文跨提取器合并仍需继续对齐，不能将必填错误汇总视为整个 MVC 绑定已经等价。

JSON 端点通过方法构建器声明正文参数名，例如 `post(create_user).json_body("createUser")`。名称对应源接口参数，不从 DTO 类型名推断，也不放到可复用模型中。空正文与根 `null` 返回非空正文及参数必填两项错误；仅含 JSON 空白字符的正文返回 `$` 语法错误及参数必填，行号与字节位置从零开始。空对象 `{}` 仍执行模型字段验证，不等同于缺少正文。

JSON 读取接受 application/json、text/json 和 application/*+json，媒体类型判断先于读取正文。UTF-8 BOM 仅从解析视图中移除；只包含 BOM 的正文属于没有 JSON token 的语法错误。原始字节保持不变，`JsonWithBody` 另按源 GetRequestBody 的 BOM/gzip 规则读取验签文本，不重新序列化已绑定对象。其他 charset 的完整转换和不支持媒体类型的 ProblemDetails 正文仍有待对齐。

字段验证通过 `#[query(validate = "函数路径")]` 声明，函数接收字段值的引用并返回 `Result<(), InputError>`；只在该字段绑定成功后执行，即使其他字段绑定失败仍执行。分页 `page_size` 使用模型层的 `validate_page_size_query`，因此格式错误与另一字段的范围错误可以一起返回。验证器属于请求声明，不用于执行业务查询或副作用。

数字字段可接收 JSON 数字或数字字符串，转换时检查目标类型范围；字符串字段不把数字或布尔值自动转成文本。查询布尔参数接受大小写不同的 `true`、`false`，JSON 布尔字段仍使用 `true` 或 `false`，不能写成字符串 `"true"`。非有限数字不参与数字字段绑定。

必填字符串为空或只有空白时，请求绑定失败；非空字符串不会因为绑定而被裁剪。Query 中没有 `Option` 或默认值的字段缺失时，宿主输出 `字段名 : The 字段名 field is required.`，不暴露 Serde 的 missing field 文案，也不为缺失字段推断类型或补造值。源端允许省略的非可空值类型参数应在 DTO 中显式声明 `#[serde(default)]`。可空请求字段按其类型声明转换：

```rust
#[serde(default, deserialize_with = "common::json_helper::deserialize_optional_json_scalar")]
pub remark: Option<String>,

#[serde(default, deserialize_with = "common::json_helper::deserialize_optional_query_scalar")]
pub is_enable: Option<bool>,
```

使用这些标注的可空字符串、数字、布尔和日期字段，将空字符串、纯空白字符串及 JSON null 视为无值。Query 版本还处理文本布尔值。新增请求 DTO 时选择与输入来源对应的转换器；不要给数组、对象、动态 JSON、响应模型或第三方协议模型添加这些标注。已有的可空长整数转换器继续兼容字符串数字与空白输入。

输入字段类型错误、格式错误或数字越界返回 HTTP 400，错误体沿用 `errMsg`。Query 的多个字段错误以 ` | ` 连接；顺序遵循源 ModelState 的树形广度遍历，同层按 UTF-16 长度、OrdinalIgnoreCase 排序，不使用请求顺序或文化排序。分页属性保留对应显示名和整体选择的参数前缀。JSON 媒体类型和编码由共享正文绑定层处理，原始字节读取沿用 Axum 正文大小限制；Query 与正文错误尚未跨提取器合并。

JSON 接受 application/json、application/*+json 和 text/json。默认 UTF-8，显式 charset 只接受源端支持的 UTF-8、UTF-16 小端及别名；不将 utf8、UTF-16 大端、ASCII 或 Latin1 自动当作 UTF-8。重复 charset 使用第一个，带引号的值保留引号内空白。UTF-16 使用严格解码，奇数字节或非法代理项进入共享内部异常响应。转码和 BOM 去除只影响解析视图，签名及 JsonWithBody 持有的仍是原始字节。

共享请求入口在任务调度和鉴权等待之前保存正文存在标记，方法绑定器与 JSON 读取复用该快照；单独调用绑定器时仍在创建回放流前补充快照。HTTP/2 接收流的结束状态受接收、读取和取消进度影响，不能在鉴权之后重新计算并覆盖入口状态。媒体类型先匹配；传输层无正文时返回必填错误，不再检查 charset。分块传输即使最终为空，也要经过编码选择与 JSON 解析，不能只按读取结果长度判断缺失正文。不支持的媒体类型或编码使用 415 application/problem+json，包含 type、title、status 与 traceId；普通长度的有效 W3C traceparent 继承 trace 并生成新 span；较新版本携带扩展时按源 Activity 生成层级 ID，超长时只在层级边界截断，不能保留边界则生成新根。重复 traceparent 按源 StringValues 跳过空值并用逗号合并后验证；旧 Request-Id 按 .NET 10 默认传播器忽略。扩展与超长追踪标识本轮仅完成源码及编译核对，完整内容协商仍待继续核对，此响应实现不代表完整分布式追踪组件。

Guid Query 参数显式使用 `common::json_helper::input::deserialize_query_guid`，复用数据导入的 Guid 解析规则，支持 N/D/B/P/X 格式并拒绝 `urn:uuid:`。非可空 Guid 省略时可通过 `#[serde(default)]` 使用空 Guid；显式空值与非法文本均由共享 Query 错误层输出标量错误。重复参数仍取第一项解析，错误中的尝试值按 StringValues 规则合并。不要在处理器中把非法 Guid 改为业务错误，或把这一转换规则加到 JSON 协议字段上。

日志、队列与 LLM 会话查询的可空日期使用 `common::json_helper::input::deserialize_optional_query_date_time`。空白视为无值；非法日期和越界值保留 Query 错误类别，并按模型声明显示 `StartTime`、`EndTime` 等属性名称。日期解析采用 invariant 规则，与签名的宿主文化排序分开；当前覆盖完整年月日的 ISO、斜杠或点分数字日期及英文月份形式，支持分钟/秒、只写小时的 AM/PM 和显式时区偏移。数字短日期按月、日、年解释，两位年份使用 2049 分界。ISO 的 T 分支要求两位时分秒，不接受 AM/PM 或 GMT 后缀；普通日期形式可用 GMT。没有偏移时使用宿主本地时区。

日期范围按本地时间和 UTC 时间均在公元 1 到 9999 年内检查，偏移不超过正负十四小时；秒的小数按源转换规则舍入到百纳秒，而非直接截断。Query 日期声明不修改 JSON 日期协议或响应序列化。省略年月日的自由形式日期、完整区域历法和夏令时无效/重叠时间尚未全部对齐，不应将上述格式支持理解为 .NET DateTimeOffset.Parse 的完整替代。

上述规则只处理输入，不改变响应字段名称、字典键或字符串内容。各接口是否允许省略参数、业务校验提示及返回模型仍由具体 DTO 和应用服务定义。


## 参数绑定与 Action 过滤器

共享控制器方法构建器先执行认证、续签和权限守卫，再按处理器签名提取参数。参数全部提取成功后才运行签名、响应缓存、请求队列和 ETag 等 Action 过滤器；业务函数只在过滤器放行后调用一次。缓存命中或过滤器拒绝时释放已绑定参数，不调用业务函数。正文限制使用绑定前的 `map`，Action 过滤器使用共享宿主内部的 `map_action`。

参数提取与过滤器通过独立读取流共享按需缓存的原正文，Query 校验失败时无需提前读完正文。JSON 模型只绑定一次；普通文件上传使用 `uploaded_file::FormFile`，在 Action 过滤器前流式读完整个表单并绑定第一个名称为 `file` 的文件。文件内容保留在同一原文缓存中，业务调用时再复制选中的部分，不增加整文件内存副本。Ueditor 保留自己的表单与大小校验规则。

普通文件端点通过 `uploaded_file::require_multipart` 选择媒体类型，非空且不是 multipart/form-data 的 Content-Type 返回空体 415，先于认证及参数绑定；错误 HTTP 方法仍先返回 405。缺少文件返回必填错误，命名文件长度为零则绑定成功，业务阶段返回请勿上传空文件。Query 与正文跨提取器错误汇总仍需继续对齐；这些规则不代表所有 MIME 头语法、字段数量及长度限制均已覆盖。

## 对象响应与缓存序列化

控制器普通对象和异步 JSON 数组逐项使用 `common::json_helper::write_controller_json`：按原始 Serde 类型将 i64（含可空值、集合和嵌套字段）写成 JSON 字符串，i32 与 u64 保持数字；DateTimeOffset 仍输出 ISO，不套用内部日期格式。动态 `Value`、`Number` 和 `RawValue` 保留 JSON 文档自身的数字类型，字典键沿用目标序列化器。非有限浮点数不能静默变成 null：普通对象返回共享内部异常，已经开始的数组流按流错误终止，不补写结束括号。事件等协议使用原有 Web JSON 助手，JWT 序列化也不经过控制器格式化。

明确声明为 DateTimeOffset 的响应字段输出最多七位小数秒并去除尾零，无小数时省略小数点；偏移始终为 `±HH:mm`，零偏移为 `+00:00`。共享 `date_time::serialize_offset` 保留类型标记，字符串承载的对应 DTO 字段使用 `serialize_offset_string` 或 `serialize_optional_offset_string`，可读回内部格式后按上下文输出。普通字符串及第三方协议字段不自动识别为日期。缓存和 ETag 的内部日期仍为 `yyyy/MM/dd HH:mm:ss zzz`；缓存命中后作为 JSON 文档返回，保留这个文本而不是重新转换 ISO。

共享文本格式化根据 `Accept-Charset` 选择 UTF-8 或 UTF-16 小端，默认 UTF-8，不写 BOM。对象 JSON、415 ProblemDetails、异步 JSON 数组和显式 `text_response::Text` 字符串结果参与；已有 UEditor 文本结果通过 `text_response::from_response` 声明。文件、静态资源、健康端点和直接返回的业务错误不参与。转换发生在对象缓存与 ETag 之后、压缩之前，按帧处理并保留跨帧字符和尾部字段，不收集整个流；转换后删除原 Content-Length。

字符集只按源格式化器的名称匹配 `utf-8`、`utf-16` 和 `*`，不扩大到编码别名。质量排序、通配符优先级、重复值和只有零质量声明时的分支遵循源 TextOutputFormatter，而非另行强制返回 406。媒体类型先由共享 `response_format` 按 `Accept` 选择，再进行字符集转换；当前字符集与媒体类型的新增路径尚无两端实际 HTTP 对照。

普通对象与异步 JSON 数组支持 `application/json`、`text/json`；字符串默认 `text/plain`，选择 JSON 时会序列化为 JSON 字符串（包括引号与转义）。ProblemDetails 保留服务端声明的 `application/problem+json`。有效 `*/*` 使整组 Accept 被忽略，不支持的类型回退默认输出，不产生 406，也不回显任意 vendor 类型。质量降序保留零质量；首个 q 之前的其他必需参数影响匹配，之后的参数不影响匹配，重复 q 使用最后值。排序沿用源 List.Sort 的分区策略，不给大量同质量条目额外承诺稳定顺序。JSON 流只更新类型并继续逐帧输出；只收集已声明为完整字符串的正文。对象缓存与 ETag 仍先于媒体类型选择。

共享 Json 和 Text 返回器保留 HTTP JSON 对象快照。响应缓存或 ETag 过滤器执行处理器期间，通过各自请求任务作用域按需收集 common::json_helper::object_to_json 的内部 JSON；普通端点不额外生成内部快照，嵌套过滤器不能互相关闭对快照的需求。缓存保存内部值及状态码，命中后字符串 JSON 恢复为 Text，其余保留 JSON 文档，不重复推断原始模型类型。Text 的响应格式选择直接使用已有快照，不重新收集正文；已有文本响应的 from_response 为异步适配器，在过滤器处理结果前读取完整 UTF-8 文本并建立快照。

ETag 对内部 JSON 求 SHA256，而非 HTTP JSON；内部日期和 long 转换参与摘要，与后续 Accept、Accept-Charset、压缩选择无关。内部序列化失败时缓存保留原响应并跳过写入，显式 ETag 则进入共享内部异常响应；不得用 HTTP JSON 作为摘要回退。null、文件、异步数组和直接业务错误继续不参与对象缓存与 ETag。

对象字段顺序沿用源 DTO 的声明顺序。源摘要针对序列化文本，因此 JSON 对象的字段集合相同也不能保证相同 ETag；不要通过全局字典排序或先转动态 JSON 消除模型的声明顺序。动态内容和字典仍遵循各自已有的顺序语义。

控制器、内部 JSON、克隆 JSON、业务错误和 ProblemDetails 的字符串使用源宽松编码规则：普通已定义 BMP 字符可原样输出，禁用字符及补充平面字符使用大写十六进制的 UTF-16 转义，常用控制字符保留短转义。字符范围表来自 .NET 10 编码器，并在生产数据文件中保留上游地址、摘要和许可证。事件的默认 Web JSON 使用默认编码器，额外转义非 ASCII 及 HTML 敏感字符；字符串结果不使用事件序列化助手。

原生 f32/f64 使用源默认 G 数字格式：最短可往返有效数字不再二次舍入，整数值不补 `.0`，保留 `-0`。十进制指数小于 -4，或分别达到 9/17 时，改用大写 E、显式正负号及至少两位指数；例如原生 f64 的 `1.0` 输出 `1`，`0.00001` 输出 `1E-05`。RawValue 和启用 arbitrary_precision 的 Number 保留文档数字原文，不按原生浮点值重新格式化；decimal 也不使用这条规则。

共享 JSON 的对象与数组最多嵌套 64 层。输出在进入下一层前检查，RawValue 文档也计入所在位置的深度；流式数组通过 `write_controller_json_array_item` 写单项，把宿主已输出的外层数组计为一层。内部 JSON、克隆和 Web 协议读取共用容器深度检查。HTTP 模型绑定在读取 token 时检查，超限通过独立错误类型交给绑定层返回 400，记录对象/数组种类、路径和起始括号的字节位置；不改写正文或影响签名原文。字符串中的括号和任意精度数字的内部 MapAccess 协议均不增加容器深度。

JsonModel 识别 String 键的 HashMap、BTreeMap、IndexMap 和 Map 字段，并声明 Dictionary 形态及元素类型。字典本身需要对象或允许的 null，字符串元素在 token 读取时检查；错误类型名称使用源 Dictionary 协议名称。`dictionary_value_name` 可显式标明源元素名称，LLM ExtraBody 声明为 JsonNode。该声明不改动键值、空白处理或后续自定义转换器。动态文档和未知字段的内部节点继续参与语法/深度检查，但不扩展读取栈错误路径；字典键和类型化列表索引仍保留。JSON 路径按源特殊字符清单选择点号或方括号形式，属性内容本身不做转义或替换。

RawValue 写回参照 JsonElement：逐个解码并重编码字符串、删除结构外空白，同时保留数字词法、重复键和字段顺序。缓存恢复也经过这一写入器，但不会把普通字符串推断为日期或 long。明确日期类型按源原生日期写入路径输出已验证 ISO 文本，默认编码器不额外转义其中的时区正号；这一例外仅保存在单次同步序列化上下文中。

UserDto.create_time 使用 DateTime<FixedOffset> 和显式偏移序列化器。首次 HTTP 响应保留 ISO 格式与小数秒，缓存使用源公共 DateTimeOffset 格式 yyyy/MM/dd HH:mm:ss zzz，因此缓存命中的日期可能与首次响应不同。模型中看起来像日期的普通字符串、动态 JSON 文档和字典内容不做日期转换。公共对象序列化与对象克隆分别选择日期策略，克隆继续保留 ISO 日期；不能为修正响应缓存而改变任务参数的克隆格式。

JSON 在对象属性或数组元素的逗号分隔处结束时，依据 MapAccess/SeqAccess 是否已经进入下一个键或值来识别 EOF，不解析 Serde 错误文案，也不将未闭合字符串里的逗号当作分隔符。直接结束在逗号上的位置指向逗号；逗号后仍有 JSON 空白时位置指向正文末尾。保持已有模型路径、UTF-8 字节列号和先发生的类型/深度错误优先级。

原读取器已报告 EOF 后，公共读取层才辨认未闭合字符串，包含属性名、字符串值、末尾反斜杠及未完成但已有数字均合法的 Unicode 转义。这个只用于诊断的字节遍历不构造模型、不分配正文副本，也不提前验证其他字段；错误位置为原 UTF-8 正文末尾。非法转义、控制字符或非十六进制字符不归类为缺少引号，已闭合字符串后的数字/字面量截断也不归类为字符串错误。其他语法错误文案仍待核对，不能视为已完成全部 JSON 错误对齐。
