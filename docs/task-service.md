# 任务服务

`presentation/task_service` 选择具体任务和业务适配器，`task_service_core` 负责调度和执行生命周期，`queue_task_database` 管理所属业务库中的队列记录。队列任务与广播事件分别使用竞争领取和每实例订阅，不混用消费机制。

配置环境按 `APP_ENVIRONMENT`、`DOTNET_ENVIRONMENT` 依次选择，未提供有效值时为 `Production`。宿主在基础 TOML 后加载对应环境 TOML，再应用 APP 环境变量；环境文件可以暂时不存在。日志过滤配置默认自动监听文件变化，开关、覆盖及故障恢复规则见[配置文件自动更新](local-file-logger.md#配置文件自动更新)。

## 默认任务

默认宿主声明六个队列任务和一个定时任务：

| 类型 | 名称 | 默认并发 / Cron |
| --- | --- | --- |
| 队列 | `MessageTask.SendSMS` | 1 |
| 队列 | `MessageTask.SendEmail` | 1 |
| 队列 | `ShowName`、`SendSMS`、`CallPhone`、`ShowNameSuccess` | 各 5 |
| 定时 | `ShowTime` | `0/1 * * * * ?` |

这些定义不预设备注，首次同步默认禁用。默认宿主不注册 Token 清理任务或旧任务别名；额外业务任务由应用自行声明和装配。

`ShowTime` 每次投递 17 条 `ShowName`，投递发生异常时记录错误并结束本次执行。`ShowName` 投递一个短信演示子任务和一个独立电话演示任务，全部子任务完成后以返回的姓名触发回调。演示任务接受空字符串和显式 JSON `null`；数据库 NULL 表示缺少参数，带参方法不会执行。空引用入队仍保存数据库 NULL，因此 `ShowName` 收到显式 `null` 后产生的两个任务会因缺参重试，不会触发完成回调。

## 短信任务

`MessageTask.SendSMS` 通过 `application_interface::services::sms::SmsService` 接收 `SendSmsDto`。参数字段为 `SignName`、`Phone`、`TemplateCode`、`TemplateParams`，区分大小写；字段及模板字典的值可为空。生产者调用 `SendSmsDto::to_queue_json()` 编码，消费者通过公共克隆读取识别对象和字典开头的 `$id`。模板字典保留输入顺序及键名大小写，重复键取最后值。

`[sms].component` 选择 `aliyun` 或 `tencent`，具体凭据在对应配置节提供。阿里云原样使用手机号和模板参数，腾讯云按模板字典顺序提取值，并在手机号前拼接 `+86`；调用方应传入符合所选组件要求的号码。两种组件都通过宿主 HTTP 客户端工厂发送请求。

内置提供商将发送异常转换为 `false`，应用服务等待发送结束但不使用这个布尔结果。因此，队列成功表示此用例已经完成，不表示短信已送达；提供商返回 `false` 不触发队列重试，正常完成流程仍可触发回调。任务参数解析失败、整个参数为 null 或其他未被提供商转换的异常仍按队列失败规则处理。

## 邮件任务

`MessageTask.SendEmail` 通过 `application_interface::services::message::MessageService` 执行邮件用例，参数为 `application_model::message::models::SendEmailDto`。JSON 字段使用 `FromDisplayName`、`ToAddresses`、`Subject`、`Body`、`IsBodyHtml` 和 `FileIdList`，字段名区分大小写。入队时可调用 `SendEmailDto::to_queue_json()`，生成对象及列表的 `$id`、`$values` 元数据；附件 ID 编码为字符串。读取同时接受普通数组和上述列表包装。

公共克隆读取在一次反序列化内登记类型化对象、字典及集合包装的 `$id`，不同对象重复声明同一个编号会导致参数读取失败。例如根对象与模板字典、邮件收件人列表与附件列表不能复用同一个 `$id`；编号按原始字符串区分大小写，不裁剪或转成整数。不同任务参数读取各自使用独立登记表。动态 JSON 文档中的同名属性仍是普通内容，不参与这项登记；该校验不代表已支持一般对象图的 `$ref` 共享身份或循环引用。

短信和邮件 DTO 使用 `ProtocolModel` 与 `#[protocol(case_sensitive)]` 按输入顺序转换每次字段赋值，字段缺失沿用默认值。重复字段取最后一次成功读取的值，但前面的类型错误不会被后面的值掩盖；例如 `IsBodyHtml` 先出现字符串、再出现布尔值仍读取失败。类型化字典也逐次转换重复键的值。被覆盖的对象或列表仍参与同一次 `$id` 登记，因此重复字段不能绕过编号唯一性检查。普通 Serde 模型没有自动获得这种逐次赋值行为，动态 JSON 文档和查询参数维持各自规则。

克隆参数中的列表与固定数组使用不同入口：`Vec<T>` 接受上述列表引用包装，固定数组 `[T; N]` 及 tuple 入口只接受普通数组，不将 `$id`/`$values` 对象解释为数组。列表中的固定数组元素同样遵守这项限制；邮件现有的两个 `Vec` 字段不受影响。

附件引用业务库中的有效文件记录，按 `FileIdList` 顺序处理。记录路径相对于任务宿主启动时的内容目录解析；部署时应保证该目录可访问附件。`file.root_path` 不作为邮件附件的备用搜索目录。缺失、软删除及重复路径会使任务失败。

本地存储直接读取文件；选择云存储组件后，每次发送都先下载附件，即使目标文件已经存在。只有邮件成功发送后才清理本次下载的文件，失败时保留；未启用云存储时，发送完成不会删除本地附件。

SMTP 由任务宿主的 `[message.smtp]` 配置提供，默认端口为 587，使用 STARTTLS。未配置时发送失败，按队列规则重试。`FromDisplayName` 留空表示不添加显示名称，附件使用记录中的名称及 `application/octet-stream` 类型。

## 队列持久化

Worker 通过 `QueueTaskStore` 契约领取、开始、续租、完成或失败任务；默认实现为 `DatabaseQueueTaskStore`。应用入队继续使用 `QueueTaskProducer`：`create` 要求传入所属模块的 `ModuleTransaction<M>`，并验证与生产者使用同一连接池；`create_single` 独立保存。宿主通过 `build_databases` 和 `TaskServiceDatabases::for_module::<M>` 选择队列目标，详见[业务模块说明](database-modules.md)。

新增任务定义默认禁用，启用后才会领取。数据库配置的 `semaphore` 覆盖定义中的默认值，必须大于零；实例按剩余容量查询候选任务，并通过共同分布式锁限制跨实例并发。各实例必须使用相同锁连接和前缀。

队列状态转换规则：

- 领取通过原始 `xmin` 比较更新，保证竞争者只有一个成功；获取并发锁失败时释放领取，不增加执行次数。
- 真正开始时设置首次、最近执行时间并增加 `count`，首次执行也计数。失败后保留原计划时间，按最近开始时间加 `5 × count` 分钟控制重试。
- 自动执行最多三次。最后一次执行中断且租约过期后，扫描会将记录收敛为 Failed，不会永久显示 Running。
- 数据库租约和并发锁分别续期。并发锁一旦确认丢失，不再尝试恢复该锁，但继续业务执行和数据库续租；数据库确认所有权丢失后停止续租。
- 续租间隔取有效租约的三分之一，最多 30 秒，不设置五秒下限；一秒租约约每 333 毫秒续期。该间隔不保证网络故障或执行器长时间阻塞时仍可及时续租。
- 完成时锁定任务记录，在同一事务中提交成功状态、子树完成状态和回调入队。父任务自身和全部子树均成功后才生成回调，重复完成不重复生成。

完成流程沿父链使用 `FOR NO KEY UPDATE` 行锁，不修改任务主键；它仍互斥状态写入，同时允许外键检查持有的 `KEY SHARE`。避免多个子任务在同一事务中先更新成功状态、再更新子树状态后，各自持有父记录的外键锁，再同时升级为 `FOR UPDATE` 形成死锁。管理端重试继续在自己的行锁事务内检查状态与租约。

回调与父子记录始终属于同一任务库。回调插入失败会回滚这次完成事务；任务的外部业务副作用可能已经发生，因此任务处理器仍需按业务标识实现幂等。

## 管理接口

`QueueTaskManagement` 绑定业务主库，提供队列查询、手动重试、配置查询和修改、参数模板名称查询及带参实例创建，不启动任务执行器。应用服务负责请求与返回模型转换，并传入当前操作人；组件不依赖业务用户表。

手动重试在同一事务的行锁内读取和判断状态，拒绝已成功或仍持有有效执行租约的任务。允许重试时清除计划时间、执行次数、首次和最近执行时间、子树完成状态及 Worker 租约，恢复 Pending；保留任务参数、父子关系和回调配置。

配置编辑不能改变实例身份：无参定义仍必须使用空参数，模板必须保留 `__args_default__`，已有带参实例必须保持非空合法 JSON。创建带参实例必须找到对应的有效模板，不复制模板并发数或 Cron；Cron 为空时由宿主回退代码声明。模板名称去重并排序，分页每次为 1 至 100 条，参数关键词按原文包含关系匹配。

配置修改和创建既可独立提交，也可使用 `_in_transaction` 入口与业务审计一起提交。事务入口返回操作快照但不提交调用方事务。任务中心已有的删除入口只允许软删除动态带参实例，不能删除定义或模板。

Release 实例每 60 秒刷新进程内运行配置，在线修改 Cron 或启停后需等待各实例的下一轮刷新；多个实例的生效时刻可能不同。清空 Cron 后恢复任务声明的默认表达式，不会把默认值写回空配置。重新启用不会补跑禁用期间错过的触发。

## 返回值与子任务

`QueueTaskHandler::execute` 适用于无返回值任务。有返回值的异步方法使用 `task_handler::queue_action` 适配，也可覆盖 `execute_with_result` 返回 `QueueTaskResult::value(value)`。返回值在完成事务锁定记录并确认所有权后才按需序列化：显式回调参数优先，只有存在回调且缺少参数时才使用返回值。`()`、`Option::None` 和 JSON `null` 不生成参数；无回调时不会执行返回值序列化。

处理器可通过上下文的 `deserialize_parameter::<T>()` 读取 JSON 参数。调用此方法表示任务需要参数，数据库 NULL 会报告缺参错误；显式 JSON `null` 才由 `Option<T>` 等可空目标类型接收。不接受 null 的类型或其他类型不匹配也会报告执行失败。无参处理器不调用此方法；入队的字符串必须先序列化为 JSON 字符串，不能直接保存未经编码的文本。

入队参数使用 `common::json_helper::object_clone_json` 编码；回调返回值由运行器调用 `object_to_json`。两者按原始 Rust 类型将 `i64` 写为 JSON 字符串，包括可空字段和集合元素；`i32`、`u64` 及动态 JSON 文档中的数字保持数字。`deserialize_parameter` 接受数字或数字字符串形式的 `i64`，其他整数不自动接受字符串，字段名按模型的 Serde 声明区分大小写。模型应明确声明对外字段名，字典键不进行大小写转换。

```rust
register_task_registry! {
    registry = registry;
    queue {
        definition: QueueTaskDefinition::new("ReturnName"),
        factory: || Ok(task_service_core::task_handler::queue_action(|context| async move {
            let name: String = context.deserialize_parameter()?;
            Ok(name)
        })),
    }
}?;
```

任务上下文的 `id` 是当前队列任务标识。创建子任务时将它作为 `NewQueueTask.parent_task_id`，并使用同一库的生产者；需要与业务数据原子提交时传入同一显式事务，不跨库传递父任务身份。

## 并行执行和停机

Release 启动时读取配置，之后每 60 秒刷新内存快照并补充缺少的任务定义。调度循环不重复查询配置表。已有的管理员配置不会被默认值覆盖；多实例同时补充定义时，依靠有效定义唯一约束，并在插入失败后重新查询确认，只有已存在相同定义才忽略该次失败。

Debug 不补充或更新数据库中的任务定义，所有任务初始禁用。菜单列出注册的队列任务、无参定时任务及数据库中已有的带参实例；不展示 `__args_default__` 占位定义。输入序号立即启用当前进程内的任务，事件订阅和已启用任务在菜单打开期间继续运行。`start` 关闭菜单继续运行，`quit` 停止整个宿主；没有标准输入时继续运行，未选择的任务保持禁用。

生产环境的新启用带参实例在下一次同步时加入；禁用或删除配置会停止该实例后续触发，已开始执行的任务继续完成。无效 Cron 暂停当前实例，Release 下次配置刷新或 Debug 再次选择后重新尝试。

队列和定时任务分别轮询，已启动的任务通过运行器持有的任务集合并行执行，单个长任务不会阻塞其他任务的调度。

注册项使用 `factory`，每次实际执行创建独立的处理器，注册或轮询阶段不提前创建。工厂可以复用宿主连接池、ID 服务等共享资源，但执行状态应归当前处理器所有。队列处理器从开始执行一直保留到完成事务和资源释放结束；定时处理器保留到本次执行结束。

处理器可覆盖异步 `close(&mut self)` 释放作用域资源，成功、失败和处理器 panic 路径都会调用。构造失败没有可释放的处理器；停机预算耗尽时取消剩余异步工作并丢弃对象，由其 Drop 释放同步资源。释放错误会记录日志，不会撤销已经提交的成功事务。

定时任务由每个实例独立触发，不使用框架级分布式锁消除副本触发。`skip_if_running` 只限制当前进程内同一个配置实例的重入。带参数实例以 `<Name>:<TaskSetting.Id>` 区分，未配置 Cron 时使用任务定义中的默认值；触发时间按宿主本地时区计算。首次观察到实例后从五秒之后寻找下一次触发，迟到超过 256 毫秒的触发会跳过，不补跑历史批次。

默认队列轮询间隔一秒，定时轮询间隔 128 毫秒，队列租约五分钟。可通过任务宿主的 `[poll]` 和 `[lock]` 配置调整。

收到 Ctrl+C、容器 SIGTERM 或事件后台故障时，宿主先停止领取新任务，继续等待已启动的执行及续租。任务、事件和日志共享 30 秒停机预算；期限耗尽时取消剩余执行，未完成队列记录由租约恢复，不作为普通业务失败提前提交。正常关闭不是外部业务操作恰好执行一次的保证。

## Cron 配置

任务注册、管理端保存和运行调度统一使用 `common::cron_helper`。表达式为 `秒 分 时 日 月 星期 [年]`，日期与星期必须且只能有一个使用 `?`。星期从 `1`（星期日）到 `7`（星期六），名称不区分大小写。

| 表达式 | 含义 |
| --- | --- |
| `0 0 0 * * ?` | 每天零点 |
| `0 */5 * * * ?` | 每五分钟 |
| `0 0 9 ? * MON-FRI` | 工作日九点 |
| `0 0 9 L * ?` | 每月最后一天九点 |
| `0 0 9 L-2W * ?` | 距月末两天的日期所对应的最近工作日九点 |
| `0 0 9 15W * ?` | 每月十五日的最近工作日九点，不跨月 |
| `0 0 9 ? * FRIL` | 每月最后一个星期五九点 |
| `0 0 9 ? * MON#2` | 每月第二个星期一九点 |

支持列表、递增步长、跨周期范围及可选年份。星期名称后的 `/n` 表示相对搜索日期的每 n 周规则（n 为 1 至 5）；数字星期的 `/n` 是星期数值步长，两者不要混用。`C` 与参考实现相同，不额外关联节假日日历。名称范围使用逐项递增，需要步长时使用数字范围。

校验只判断语法，不保证当前时间之后仍有触发日期。调度搜索上限为进程首次初始化时的本地年份加一百年；已耗尽的年份或无法构造的日期会暂停实例，等待下一次配置刷新。计算首先读取宿主本地日历，输出时采用本地标准偏移，遵循参考实现的 `BaseUtcOffset` 行为。

公共入口为 `validate`、`get_next_occurrence`、`get_next_occurrences`，也可以解析一次 `CronExpression` 后重复调用 `next_after`。留空的数据库 Cron 保持空值，运行时取任务声明默认值。
